Glossary

The shared vocabulary of the track. Every term here is fair game to drop in an interview. Grows one chapter at a time.

Distributed system Ch 1
An application made of multiple components running on multiple machines, coordinating over a network to act as a single service. Reliability and scale come from the coordination, not any one box.
Pattern Ch 1
A reusable, named solution to a recurring design problem. It's not code you copy — it's a shape of solution you recognize and adapt. Naming it gives a team a shared language.
Practice Ch 1
A repeatable way of working that reliably produces good systems (e.g. code review, health checks, canary rollouts). Patterns are *what* to build; practices are *how* you work.
Component Ch 1
A reusable, independently-deployable building block (often a container) with a defined interface. Components let you assemble a system from parts instead of writing everything from scratch.
Container Ch 1
A packaged unit of software with its code and dependencies, isolated so it runs the same anywhere. The book's basic unit of reuse — most patterns are arrangements of containers.
Orchestrator (Kubernetes) Ch 1
The system that places, runs, connects, and heals containers across many machines. Kubernetes is the book's default. It's the substrate the patterns are expressed on.

Term unclear or missing? Ask your teacher — this glossary is meant to be corrected and extended.
