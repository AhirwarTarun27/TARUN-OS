The Scaling Ladder

The compressed essence of "Scale from Zero to Millions." Memorize the order and the one-line reason for each rung. This is your interview narration script.

  1. Single server. DNS → one box (app + DB + cache). Start simple.
  2. Split web / data tier. DB on its own machine → scale tiers independently.
  3. Horizontal > vertical. Up = ceiling + SPOF. Out = capacity + redundancy.
  4. Load balancer. Public IP front; spreads traffic; removes web-tier SPOF.
  5. DB replication. Master = writes, replicas = reads. Reliability + failover.
  6. Cache. In-memory hot reads (read-through). Near the server.
  7. CDN. Static assets from the edge, near the user.
  8. Stateless web tier. Session → shared store → autoscale freely.
  9. Multiple data centers. geoDNS routing; survive a DC outage.
  10. Message queue. Decouple + async; scale workers independently.
  11. Shard the database. Split by sharding key → scale writes + storage.

The "name the considerations" table

Interviewers reward you for naming the gotchas before they ask. Keep these on the tip of your tongue.

Cache

When to use (read-heavy) · TTL / expiration · consistency with source of truth · eviction (LRU) · it's a SPOF unless replicated.

CDN

Cost (cache only hot assets) · TTL · fallback if CDN down · invalidation when assets change.

Sharding

Resharding (→ consistent hashing, Ch 5) · celebrity / hotspot problem · cross-shard joins get hard.

Multi data center

Traffic redirection (geoDNS) · data synchronization across DCs · consistent test / deploy.

Glossary — Chapter 1 terms

  • Web tier / data tier — the request-handling layer vs the storage layer; scaled separately.
  • Vertical scaling — a bigger single machine. Horizontal scaling — more machines.
  • Load balancer — distributes incoming traffic across web servers over private IPs.
  • Replication (master/replica) — master takes writes, replicas take reads; enables failover.
  • Replication lag — a replica trailing the master → temporarily stale reads.
  • Cache — fast in-memory store for hot data. Read-through — check cache, then DB on miss.
  • CDN — geographically distributed edge servers caching static content near users.
  • Stateless — server holds no session state; any node can serve any request.
  • SPOF — single point of failure; a component whose death takes the whole system down.
  • Message queue — buffer that decouples producers from consumers for async work.
  • Sharding — splitting one database into many by a sharding key; scales writes + storage.
  • Sharding key — the column that decides which shard a row lives on (e.g. user_id).
  • geoDNS — DNS that returns a different IP based on the user's location.
