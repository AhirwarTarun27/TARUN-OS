Conditionals: if, elif, else

You've written if in JS a thousand times. Python's version does the same job with no brackets, no braces, and one new word. The real lessons here are the JS habits that still run but read wrong, plus one JS trap that gives a different answer. About 20 minutes.

How this page works Same as before: JavaScript next to Python, red boxes for JS habits that break, and a New words in this section box at the end of each section. Every output was run on Python 3.14 (and Node for the JS side) before it was written down.

0. Warm-up (cold, no scrolling back)

Answer in your head or on paper before opening each one.

not (raining and cold)
G1: write the same thing with no brackets.

not raining or not cold. "Not both" means "at least one of them isn't". When you push the not inside, each piece gets its own not and the and flips to or. Writing not raining and not cold means "neither", which is a different question. This flip has a name, De Morgan's law, and it comes up in every if you write.

print(20 - 5 + 3, 12 / 4 * 3)
G2: what prints?

18 9.0. - and + are a tie, so left to right: 20 - 5 first. / and * are a tie too: 12 / 4 is 3.0, then * 3. And / always gives a float.

not year % 4 == 0
G3: write this the clearer way.

year % 4 != 0. Same meaning, and nobody can misread it as (not year) % 4.

1. if and else: same idea, less punctuation

A conditional is code that only runs when something is true. The line that starts it is called an if statement, and the test after if is the condition. Each possible path through it is a branch: the if branch or the else branch. Choosing which code runs next is called control flow, and conditionals are the most basic control flow tool.

JavaScript 
if (temperature > 30) {
  console.log("Hot");
} else {
  console.log("Fine");
}
Python 
if temperature > 30:
    print("Hot")
else:
    print("Fine")

Three changes, all from Lesson 1:

  • No brackets around the condition.
  • A colon : ends the condition line, and else gets one too.
  • No braces. The indented lines under it are the block. Four spaces.

Forget the colon or the indent and Python stops before running anything:

if temperature > 30
SyntaxError: expected ':'

if temperature > 30:
print("Hot")
IndentationError: expected an indented block after 'if' statement on line 2
JS habit: brackets after if if(x > 3): still runs. Python reads the brackets as plain grouping, like (2 + 3), so nothing breaks. But it's the clearest sign of "a JS developer wrote this", and the style guide (PEP 8) says to leave them out. Write if x > 3:, with one space after if.

2. elif: more than two branches

JS writes else if. Python squashes it into one word: elif. You can have as many as you like. Python checks them top to bottom and runs only the first branch whose condition is true. The rest are skipped, even if they'd also be true.

JavaScript 
function ticketPrice(age) {
  if (age < 5) {
    return 0;
  } else if (age < 18) {
    return 50;
  } else if (age >= 60) {
    return 70;
  } else {
    return 100;
  }
}
Python 
def ticket_price(age):
    if age < 5:
        return 0
    elif age < 18:
        return 50
    elif age >= 60:
        return 70
    else:
        return 100
ticket_price(3)     0
ticket_price(17)    50
ticket_price(18)    100
ticket_price(65)    70

Order matters

A 3-year-old is also under 18. If you swap the first two branches, age < 18 catches the 3-year-old first, and ticket_price(3) gives 50. Same lesson as Leap: check the narrow, special case before the wide one.

Test the boundaries

A boundary is the exact value where the answer switches, like 18 here. Is an 18-year-old a child? That depends on < vs <=, and it's where most bugs hide. When you test, always try the value just below, exactly on, and just above each boundary: 17, 18, 19. Values like these are called edge cases.

No switch Python has no switch like JS. An if / elif chain does that job. Python 3.10 added a newer tool called match, which Exercism teaches later as its own concept.

3. elif or separate ifs?

These two look almost the same. They're not:

One chain 
n = 15
if n % 3 == 0:
    print("three")
elif n % 5 == 0:
    print("five")
three
Two separate ifs 
n = 15
if n % 3 == 0:
    print("three")
if n % 5 == 0:
    print("five")
three
five

15 is divisible by both. The chain stops after the first true branch. Two separate ifs are two separate questions, so both run. Pick by asking: can more than one of these be true and should they all happen?

  • Only one can ever apply (a price, a colour band, a status): use one elif chain. Exercism calls these branches mutually exclusive, meaning "if one is true, the others can't be".
  • Each one can apply on its own: use separate ifs.

The early return shortcut

return ends the function on the spot. So if every branch returns, a plain if after it already behaves like elif. Writing a function this way is called the early return style:

def size(n):
    if n > 100:
        return "big"
    if n > 10:          # only reached when n <= 100
        return "medium"
    return "small"

size(500)     'big'
size(50)      'medium'
size(5)       'small'

Both styles are fine. Exercism's hints mention that a linter may complain about many returns in one function. A linter is a tool that reads your code and flags style problems without running it. It's a style opinion, not an error, so your tests still pass.

4. When the answer is True or False, skip the if

You met this in Leap. A comparison already is True or False (Lesson 2), so wrapping it in an if just to return those same values is a step too many:

Long way 
def is_adult(age):
    if age >= 18:
        return True
    else:
        return False
Python way 
def is_adult(age):
    return age >= 18

is_adult(20)    True
type(is_adult(20))
<class 'bool'>

Rule of thumb: if the function returns True/False, return the condition itself. If it returns something else (a word, a number, a price), that's when you need if/elif.

Truthy values work in if too

The spot right after if is a boolean context: a place where Python needs True or False. Give it any other value and Python quietly runs bool() on it, using the truthy/falsy rules from Lesson 2. So you can test "is this empty?" directly:

JavaScript 
if (items.length > 0) { ... }
if (isOpen === true) { ... }
Python 
if items:      # empty list is falsy
    ...
if is_open:    # not: if is_open == True
    ...
JS habit: empty list is truthy In JS, if ([]) runs, because every array is truthy. In Python, an empty list is falsy, so if []: skips. Same for {}, "" and 0.

Boolean context
A place where Python needs True or False, like right after if. Any other value gets passed through bool() there.same idea, different falsy list

5. Chained comparisons and nesting

Python lets you write a range check the way you'd write it in maths. This is called a chained comparison:

16 <= age < 18      # means: 16 <= age and age < 18

Python splits it into two comparisons joined by and. Each value in the middle is used by both sides. That's handy for "is this number inside a range?".

Same code, different answer JS doesn't chain. It does the first comparison, gets true or false, then compares that with the next number, treating true as 1.
JavaScript 
3 > 2 > 1     false
// (3 > 2) → true → true > 1
// → 1 > 1 → false
1 < 3 < 2     true
Python 
3 > 2 > 1     True
# 3 > 2 and 2 > 1

1 < 3 < 2     False
Python gives the answer you'd expect from maths.

Nesting

An if inside another if is a nested conditional. It works, but every level pushes the code further right. When the inner if has no else, you can usually join the two conditions with and instead:

Nested 
if age >= 18:
    if has_licence:
        print("Can drive")
Flat, same result 
if age >= 18 and has_licence:
    print("Can drive")

Chained comparison
a < b < c means a < b and b < c. Good for range checks. doesn't exist: JS gives a different answer
Nested conditional
An if inside another if. Often you can flatten it with and. same in JS

6. The one-line version: x if test else y

First, two words. An expression is code that produces a value, like 2 + 3 or age >= 18. A statement is code that does something but isn't a value, like an if block or return. You can put an expression inside print(...), but not a statement.

Sometimes you want an if that is a value. JS has ? : for that, called the ternary operator. Python's version is called a conditional expression, and it reads in a different order:

JavaScript 
const label = n % 2 === 0 ? "even" : "odd";
Python 
label = "even" if n % 2 == 0 else "odd"
JS habit: the order is different JS puts the test first: test ? yes : no. Python puts the "yes" value first: yes if test else no. Read it as an English sentence: "even, if n is divisible by 2, otherwise odd". ? : doesn't exist in Python at all.

Use it only for short, simple choices. If it doesn't fit comfortably on one line, write a normal if/else.

New words in this section

Expression / statement
An expression produces a value (2 + 3). A statement does something but isn't a value (if, return). Only expressions fit inside print(...). same split in JS
Conditional expression / ternary
yes if test else no. A one-line if that produces a value. test ? yes : no

7. Stopping on bad input: raise

Sometimes the right answer is "this input is wrong, stop". Python stops a program by creating an exception: an error object that halts the code and reports what went wrong. You've already met some, like TypeError and ValueError. To create one yourself, you raise it, which is Python's word for JS's throw:

JavaScript 
if (level < 0 || level > 10) {
  throw new Error("volume must be between 0 and 10");
}
Python 
if level < 0 or level > 10:
    raise ValueError("volume must be between 0 and 10")

No new, and you pick the error's type. ValueError is the usual one for "right type, bad value". The text in brackets is the message people will read. Like return, raise ends the function at once, so nothing after it runs. Here's the full error report Python prints, called a traceback. Read it from the bottom: the last line is the error type and your message.

def set_volume(level):
    if level < 0 or level > 10:
        raise ValueError("volume must be between 0 and 10")
    return level

print(set_volume(11))
Traceback (most recent call last):
  ...
ValueError: volume must be between 0 and 10

An if at the top of a function that rejects bad input before the real work starts is called a guard clause. The rest of the function can then trust its input. Catching exceptions with try/except (JS's try/catch) gets its own bridge lesson later. For now, raising is all you need.

Check yourself: 5 questions

From memory. Getting it wrong here costs nothing.

1. In an if / elif / else chain, which branches run?

Only the first true one. Python stops checking after the first true branch. If you want every true test to run, use separate ifs.

2. What does 3 > 2 > 1 give in Python?

True. Python chains comparisons like maths. JS gives false, because it turns 3 > 2 into true and then checks true > 1, which is 1 > 1.

3. Which is Python's version of ok ? "yes" : "no"?

"yes" if ok else "no". The "yes" value comes first, then the test. ? : doesn't exist in Python.

4. Best way to write this?
if x > 0: return True / else: return False

return x > 0. The comparison already is True or False. The first option works too, but it's the same extra step squeezed onto one line.

5. JS has throw new Error("bad"). What's the Python?

raise ValueError("bad"). No throw, no new. Careful: return ValueError("bad") doesn't stop anything. It just hands back the error object as an ordinary value.

x = 0
if x:
    print("yes")
else:
    print("no")
P1 answer

no. 0 is falsy, so the if branch is skipped.

n = 30
if n % 3 == 0:
    print("A")
elif n % 5 == 0:
    print("B")
if n % 2 == 0:
    print("C")
P2 answer

A then C. 30 divides by 3, so the chain stops at A and skips B. The last if starts a new, separate question, so C runs too.

print(1 < 3 < 2)
P3 answer

False. It means 1 < 3 and 3 < 2, and the second part is false. JS would print true.

age = 20
print("adult" if age >= 18 else "minor")
P4 answer

adult. The test is true, so you get the value before if.

def check(n):
    if n > 10:
        return "high"
    if n > 5:
        return "mid"

print(check(3))
P5 answer

None. Neither test is true, so no return runs. A function that finishes without returning gives None (Lesson 1). That's a common bug: a branch you forgot.

def check_age(age):
    if age < 0:
        raise ValueError("age can't be negative")
    return age

print(check_age(-1))
P6 answer

ValueError: age can't be negative, at the bottom of a traceback. The raise stops everything, so return age and the print never run.
