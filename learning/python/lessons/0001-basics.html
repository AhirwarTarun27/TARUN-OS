Basics: names, functions, comments, docstrings

You already know how to program. This lesson shows the 8 places Python does things differently from JavaScript. Most of them are places where JS is relaxed and Python is strict. About 20 minutes.

How this course works You follow Exercism's Basics chapter. This page teaches the same chapter, but written for someone who already knows JavaScript. Every section puts JavaScript next to Python, and the red boxes point out a JS habit that will break here. Any new word is explained in a New words in this section box at the end of the section where it first appears, so you never have to scroll away. All of them are also collected in the glossary. When you finish, do the Exercism exercise.

Every output on this page was run on Python 3.14 before it was written down.

0. How Python runs your code (60 seconds)

Python works like Node. You write a file, lasagna.py, and run it with python lasagna.py. That python program is called the interpreter: it reads your file from top to bottom and runs each line, just like node does for JS. On Exercism you don't even need that, because the website runs your code and its tests for you.

What you'll notice at once:

  • No semicolons. One line, one statement.
  • No curly braces. Indentation (the spaces at the start of a line) marks the blocks. More in §3.
  • No let, const or var. More in §1.
  • print() is your console.log(). Give it several values and it puts a space between them.
JavaScript 
console.log("a", "b", 3);
a b 3
Python 
print("a", "b", 3)
a b 3

Type python with nothing after it and you get the REPL, a prompt that looks like >>>. It's the browser console for Python: type a line, see the result.

New words in this section

Interpreter
The program that runs your Python code, python. Is Python compiled or interpreted? Both: it quietly compiles your file to an in-between form, then runs that. You never have to care. like node
REPL
Read, Evaluate, Print, Loop: the >>> prompt you get by typing python. It shows the result of each line, except None, which it doesn't print. the browser console, or node with no file

1. A name points at a value

In JS you declare a variable with a keyword. In Python you just write the name and =. The first time you assign to a name, Python creates it.

JavaScript 
let myFirstVariable = 1;
myFirstVariable = "now a string";
Python 
my_first_variable = 1
my_first_variable = "now a string"

Python people say "variable", but they also say name. The idea: a name is a label you stick on a value, not a box that holds it. x = 1 sticks the label x on the value 1. This is called binding the name. Same idea as a JS variable that holds a reference.

Dynamic: a name can point at any type

Above, the same name pointed at a number and then at a string. Python allows that, just like JS. That is what dynamically typed means: the type belongs to the value, not to the name.

Strong: Python won't quietly convert types for you

This is the first big difference. Remember JS coercion from your JS course, Lesson 1? Python refuses to do it.

JavaScript 
"1" + 1
"11"   // JS turns 1 into "1"
Python 
"1" + 1
TypeError: can only concatenate
str (not "int") to str

That is what strongly typed means: mixing types in a way that doesn't make sense is an error, not a guess. If you want "11", you convert yourself: "1" + str(1).

JS habit that breaks here "Dynamic" and "strong" are two different questions. Dynamic: can a name change type? Yes, in both languages. Strong: will the language convert types behind your back? JS will. Python won't. So Python is dynamic and strong, and JS is dynamic and weak.

Using a name before you assign it

Using a name Python has never seen gives NameError: name 'y' is not defined. This is JS's ReferenceError under another name. You'll mostly see it when you make a typo.

Exercism's intro uses two more typing words. You don't need either for the exercise:

  • Duck typing: "if it walks like a duck and quacks like a duck, it's a duck". Python only cares whether a value has the method you call, not what its type is called. JS works the same way.
  • Type hints: optional labels like def ask(question: str) -> str:. Python doesn't enforce them, but tools and libraries read them. Since you can add them bit by bit, Exercism calls this gradual typing. Think TypeScript annotations that Python runs fine without.

New words in this section

Name / binding
A name is Python's word for a variable. Binding means sticking a name on a value with =. a variable that holds a reference
Dynamically typed
A name can point at any type, and change type later. Types are checked while the program runs. same as JS
Strongly typed
Python won't quietly convert one type into another. "1" + 1 is an error. the opposite of JS coercion
TypeError
The value is the wrong kind for what you asked, like adding a number to a string. (In §5 you'll see it also covers calling a function with the wrong number of arguments.) TypeError, but Python raises it far more often
NameError

2. Constants are just a naming habit

Python has no const. A constant is a name you promise never to change, and you show that promise by writing it in SCREAMING_SNAKE_CASE. You put it at the top of the file, outside any function. That spot is called module level.

JavaScript 
const MAX_TOKENS = 500;
MAX_TOKENS = 600;
TypeError: Assignment to
constant variable.
Python 
MAX_TOKENS = 500
MAX_TOKENS = 600
print(MAX_TOKENS)
600   # no error at all
JS habit that breaks here In JS, const is a rule the engine enforces. In Python, capital letters are only a message to other programmers: "don't change this". Python won't stop you. Exercism calls changing one "VERY strongly discouraged". Don't do it.

Naming style: snake_case, not camelCase

WhatJavaScriptPython (PEP 8)
Variables, functionsbakeTimeRemainingbake_time_remaining
ConstantsMAX_TOKENSMAX_TOKENS
Classes (later)ChatClientChatClient

The style rules come from PEP 8, Python's official style guide. PEP stands for Python Enhancement Proposal: an official, numbered document about Python. You'll see three of them: PEP 8 (style rules), PEP 257 (how to write docstrings, §7) and PEP 20, "The Zen of Python", a list of short sayings like "Explicit is better than implicit." Type import this in the REPL to read it.

Also avoid one-letter names like x in real code. Use names that say what the value is.

Why this matters on Exercism Exercism's tests import your names by their exact spelling. A constant with the wrong name or wrong case fails the test, even if the value is right.

3. Functions: def, a colon, and indentation

JavaScript 
function addTwoNumbers(a, b) {
  const total = a + b;
  return total;
}
Python 
def add_two_numbers(number_one, number_two):
    total = number_one + number_two
    return total

Read the Python version piece by piece:

  • def is Python's function keyword. It's short for "define".
  • The parameters go in brackets, like JS. Parameters are the names in the def line (number_one, number_two). The values you pass in when you call it, like add_two_numbers(2, 3), are the arguments. Same meaning as in JS.
  • The line ends with a colon :. The colon means "a block starts on the next line".
  • The body is indented. PEP 8 says 4 spaces. The body ends where the indentation ends. There is no closing brace.
  • return sends a value back, same as JS.
JS habit that breaks here In JS, indentation is only for looks. The braces decide what's inside the function. In Python, indentation is the syntax. Python people call this significant indentation: the spaces change what the code means. Get it wrong and the code doesn't run at all: 
def f():
return 1
IndentationError: expected an indented block after
function definition on line 1
Same if one line is indented more than the lines around it: IndentationError: unexpected indent. The Exercism editor indents for you, so mostly just keep lines lined up.

New words in this section

Block / significant indentation
A block is a group of lines that belong together, like a function body. Python marks blocks with a colon and indentation. "Significant" means the indentation changes what the code does. what { } do
Argument vs parameter
The parameter is the name in the def line (number_one). The argument is the value you pass when you call it (5).same meaning as in JS
IndentationError
The spaces at the start of a line are wrong, so Python can't tell where a block starts or ends. The file doesn't run at all.no equivalent, JS ignores indentation

4. No return gives you None

A JS function without return gives back undefined. A Python function without return gives back None. Same for a bare return with nothing after it.

JavaScript 
function square(n) {
  const sq = n * n;    // forgot return
}
console.log(square(4));
undefined
Python 
def square(n):
    sq = n * n         # forgot return

print(square(4))
None

None is Python's single "nothing here" value. There is no separate null and undefined. Python has one, None, with a capital N.

New words in this section

None
Python's one "no value" value. Functions without return give it back. null and undefined, merged into one

5. Wrong number of arguments is an error

This is the most important habit to unlearn. JS lets you pass too many or too few arguments and quietly carries on. Python stops you.

JavaScript 
function add(a, b) { return a + b; }

add(1)        NaN  // b is undefined
add(1, 2, 3)  3    // 3 is ignored
Python 
def add(a, b):
    return a + b

add(1)
TypeError: add() missing 1 required
positional argument: 'b'
add(1, 2, 3)
TypeError: add() takes 2 positional
arguments but 3 were given

Both are a TypeError. Read the message: it tells you the function name, how many arguments it wanted, and which one is missing. Python error messages are worth reading in full.

Both messages say positional argument. That's an argument matched to a parameter by its position: the first value goes to the first parameter, the second to the second. In add(1, 2), 1 goes to a and 2 goes to b. Every JS argument works this way.

Coming later Python can make an argument optional by giving it a default value, and you can pass arguments by name, like create(model="...", messages=[...]). Every AI library call looks like that. It has its own bridge lesson after the Exercism chapters it needs.

New words in this section

Positional argument
The word in both error messages. An argument matched to a parameter by its position: the first value goes to the first parameter, the second to the second. In add(1, 2), 1 goes to a and 2 goes to b. (The other kind, passing by name, is the "Coming later" note above.) every JS argument is positional

6. Dot notation: methods live on the type

You call methods with a dot, like JS. Strings have .upper() where JS has .toUpperCase().

JavaScript 
"hi".toUpperCase()
"HI"
String.prototype.toUpperCase.call("hi")
"HI"
Python 
"hi".upper()
'HI'
str.upper("hi")
'HI'

Exercism shows both forms. The second one is the same idea as the prototype lesson in your JS course: the method doesn't live on the string "hi". It lives on the string type, str. "hi".upper() is a shortcut for str.upper("hi"). You will almost always write the first form.

New words in this section

str
Python's name for the string type. You'll also use it to convert: str(1) gives "1".the String type, and String(1)
Method
A function that belongs to a type and is called with a dot, like .upper(). same as JS methods

7. Comments and docstrings

Comments

JavaScript 
// one line
const x = "foo"; // inline
/* many
   lines */
Python 
# one line
x = "foo"  # inline
# many lines?
# one # per line

# starts a comment, and the comment ends at the end of the line. Python has no /* */. For several lines, put a # on each one.

Docstrings: documentation that stays with the function

A docstring is a string in triple double quotes, """like this""", placed as the first line inside the function body. A comment disappears when the code runs. A docstring doesn't: Python saves it on the function, and you can read it while the program runs.

def ask(question):
    """Send one question to the model and return its answer."""
    return "42"

print(ask.__doc__)
Send one question to the model and return its answer.

help(ask)
Help on function ask in module __main__:

ask(question)
    Send one question to the model and return its answer.

Names wrapped in two underscores on each side, like __doc__, are called dunder names (short for "double underscore"). Python uses them for its own special features, and you'll meet more, like __init__.

A function without a docstring has __doc__ set to None. Longer docstrings can list the parameters and what the function returns. Exercism's chapter shows that format, and the style rules are in PEP 257.

Closest JS thing 
/**
 * Send one question to the model.
 */
function ask(question) { ... }
The difference 
# JSDoc is a comment. The running
# program can't see it.
# A docstring is a real value
# on the function: ask.__doc__
Why an AI engineer cares In AI apps, a model (the AI that reads text and writes a reply, like GPT or Claude) can be given tools: ordinary Python functions it's allowed to ask your code to run. The model needs to know what each tool does, and some libraries get that from the docstring. OpenAI's Agents SDK (a library a company ships so you can use their service from code, like an npm client package) says it plainly: "Tool description will be taken from the docstring of the function" (source). So a docstring isn't only for humans. In that case the model reads it too.
Heads up for the exercise Exercism's first exercise tests that your functions have docstrings. It checks __doc__. Skip them and a test fails.

New words in this section

Docstring
A triple-quoted string as the first line of a function. Python keeps it on the function, so you can read it with __doc__ or help().JSDoc, but the running program can see it
Dunder (__doc__)
"Double underscore". Names wrapped in two underscores on each side are special names Python uses itself. You'll meet more (__init__, __name__). a bit like __proto__
Model / tool / SDK AI words from the box above
Model: the AI that reads text and writes a reply, like GPT or Claude. Tool: a function you let the model ask to run. SDK: a library a company ships so you can call their service from code.an SDK is like an npm client package, e.g. the Stripe SDK

8. Everything is an object

Exercism says "everything in Python is an object". In practice it means every value has a type, and you can ask for it with type(). That includes functions and even None.

type(42)       <class 'int'>
type("hi")     <class 'str'>
type(None)     <class 'NoneType'>
type(add)      <class 'function'>

f = add        # a function is a value, just like in JS
f(2, 3)        5

Two new type names in that output: int is the whole-number type (Lesson 3 covers it), and NoneType is the type of None, which is its only value.

You already know this idea from JS: functions are values you can store in a variable and pass around. Python goes all the way, and numbers, strings and None are objects with methods too. Anything you can call with (), like a function, is called a callable.

Exercism's intro also says Python supports imperative, functional and object-oriented styles. Imperative = step-by-step instructions. Functional = building results by passing data through functions. Object-oriented = grouping data and its methods into classes. You already mix all three in JS and React. It's a description of Python, not something to learn now.

New words in this section

Object
Any value in Python: a number, a string, a function, None. Every object has a type and can have methods.wider than JS's "object". In Python even 42 is one
int / NoneType
Two more type names from the type() output. int = whole numbers. NoneType = the type of None, and None is its only value. JS has one number type. Python splits whole numbers from decimals (next chapters)
Callable
Anything you can call with (). Functions are callables. Later, classes and some objects will be too."something you can invoke"
Imperative / functional / object-oriented
Three styles of writing code. Imperative: step-by-step instructions. Functional: build results by passing data through functions. Object-oriented: group data and its methods into classes. Python supports all three.same three styles you already mix in JS and React

Check yourself: 5 questions

Answer from memory before scrolling back up. Getting it wrong here costs nothing.

1. x = 5 then x = "five". What happens on the second line?

Right. Python is dynamically typed: a name can be re-bound to a value of any type. Strong typing is about converting types, not about changing what a name points at.

2. What does "Total: " + 3 give in Python?

TypeError. Python is strongly typed and won't turn 3 into "3" for you. Write "Total: " + str(3). (A later bridge lesson shows the nicer way, f-strings.)

3. def greet(name, greeting): is called as greet("Tarun"). What happens?

Right. TypeError: greet() missing 1 required positional argument: 'greeting'. JS would run it with greeting as undefined. Python doesn't.

4. Where does a docstring have to go?

Right. It must be the first statement in the body. Only then does Python save it as __doc__. A # comment is thrown away when the code runs.

5. MAX_TOKENS = 500, then MAX_TOKENS = 600, then print(MAX_TOKENS)?

600. Capital letters are a convention, not a lock. That's the difference from JS const. So the rule is on you: never re-assign one.

Predict the output: 6 snippets

Say the output out loud, and if it's an error, say the error's name. Then open the box. Naming the error is half the point.

def add(a, b):
    return a + b

print(add(1, 2, 3))
P1 answer

TypeError: add() takes 2 positional arguments but 3 were given. JS would print 3 and ignore the extra argument. Python refuses.

print("ha" * 3)
print(1 + "1")
P2 answer

First line: hahaha. Second line: TypeError: unsupported operand type(s) for +: 'int' and 'str'. Strong typing doesn't mean types can never meet. It means Python only does what's defined. "Repeat a string 3 times" is defined. "Add a number to a string" isn't.

def square(n):
    result = n * n

print(square(4))
P3 answer

None. The function works out 16 and then throws it away, because there's no return. Not undefined, not 16.

message = "hello"
print(mesage)
P4 answer

NameError: name 'mesage' is not defined. Did you mean: 'message'? A typo creates a name Python has never seen. JS would call it a ReferenceError. Notice the last part: Python spots the close match and suggests it. Another reason to read the whole error.

def ask(question):
    """Send one question to the model."""
    return "42"

def shout(text):
    return text.upper()

print(ask.__doc__)
print(shout.__doc__)

Send one question to the model. and then None. shout has no docstring, so its __doc__ is None. That's exactly what Exercism's docstring test checks for.
