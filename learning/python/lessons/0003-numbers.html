Numbers: int, float, and the maths operators

JS has one number type. Python has two you'll use every day, and that one change explains most of this chapter. Plus a few spots where Python stops with an error and JS quietly gives you a strange answer. About 20 minutes.

1. Two kinds of number: int and float

In JS, 3 and 3.5 are both just number. Python splits them:

  • int, short for integer: whole numbers. 3, -12, 1234.
  • float, short for floating point: numbers with a decimal point. 3.5, 0.0, and 3.0 too. "Floating" because the decimal point can sit anywhere among the digits.
JavaScript 
typeof 3        "number"
typeof 3.0      "number"
Python 
type(3)         <class 'int'>
type(3.0)       <class 'float'>
3 == 3.0        True

They're different types, but they compare as equal and mix freely in maths. When you mix them, the answer is a float: 3 + 4.0 is 7.0. Exercism calls this widening. It calls the int the narrower type and the float the wider one, because a float can hold everything an int can, plus decimals. So when they meet, the int is widened into a float.

Exercism also lists a third type, complex, for maths with imaginary numbers (written like 2 + 3j). It's used in science and engineering, not in web or AI apps, so you can skip it.

Whole numbers never overflow

Python ints have arbitrary precision: no fixed size limit. An int can be as big as your memory allows, and it stays exact.

JavaScript 
2 ** 100
1.2676506002282294e+30  // rounded
2n ** 100n
1267650600228229401496703205376n
Python 
2 ** 100
1267650600228229401496703205376
# exact, no "n" needed

Python's int behaves like JS's BigInt, but it's the default. You'll see one Exercism test for this chapter expect the answer 4017094016600, and Python handles it without any special effort.

2. The maths operators

+, - and * work like JS. The interesting ones are about dividing:

OperatorDoesExampleJS way
/divide, always gives a float6 / 2 → 3.06 / 2 → 3
//floor division: divide, then round down to a whole number ("floor" = the level below)7 // 2 → 3Math.floor(7 / 2)
%modulo: the remainder, what's left over7 % 4 → 37 % 4
**exponentiation: raise to a power2 ** 3 → 82 ** 3
 
6 / 2        3.0     # float, even though it divides evenly
7 // 2       3       # how many whole 2s fit in 7
7 % 2        1       # what's left over
4 ** 0.5     2.0     # square root

A useful way to see // and %: they're a pair. 7 // 2 is "how many whole 2s fit" (3), and 7 % 2 is "what's left" (1).

All of these are binary operators: they take two values, one on each side (a // b). "Binary" here just means "two". It has nothing to do with binary numbers. Exercism uses this phrase when it says ints get widened "with the binary arithmetic operators".

Catch 1: // with a float gives back a float // rounds down, but it keeps the type. If either number is a float, the answer is a float: 
7 // 2       3
127.5 // 5   25.0    # not 25
Exercism's own hint for this chapter warns about exactly this. If you need a real int, §3 shows how to convert.
Catch 2: dividing by zero is an error JS gives you Infinity and carries on. Python stops:
JavaScript 
1 / 0
Infinity
Python 
1 / 0
ZeroDivisionError: division by zero
Same for 1 // 0 and 1 % 0. It's the same pattern as Lesson 1: where JS guesses, Python refuses.
Catch 3: negative numbers (rare, just know it) // always rounds down, so -7 // 2 is -4, not -3. And % follows it: -7 % 3 is 2 in Python but -1 in JS. With positive numbers (like money in this exercise), both languages agree.

3. Converting: int() and float()

Remember "strong typing" from Lesson 1: Python won't convert for you. So you convert yourself. Turning a value into another type on purpose is called type conversion. Exercism's hints call it type casting. Same thing.

One detail about int() on a float: it truncates, meaning it cuts off the decimals without rounding. 3.99 becomes 3, not 4.

int(3.99)       3       # cuts off the decimals, does NOT round
float(3)        3.0
int(6 / 2)      3       # turns the 3.0 into a real int
int("42")       42      # text to number
float("4.5")    4.5
JS habit that breaks here JS's parseInt reads as much as it can and quietly ignores the rest. Python's int() wants the whole text to be a whole number:
JavaScript 
parseInt("4.5")   4
Number("abc")     NaN
Python 
int("4.5")
ValueError: invalid literal for
int() with base 10: '4.5'
int("abc")
ValueError: invalid literal for
int() with base 10: 'abc'
There's no NaN surprise later. You get an error on the line that went wrong. It's a ValueError: the type is fine (int() accepts text), but this particular value can't be read as a whole number.
Where you'll see this in AI code An AI model always replies with text. Ask it for a number and you get back "42", a string. int("42") turns it into a number, and if the model replied with something that isn't a number, you get a ValueError instead of a silent bug.

4. Rounding: round()

round(3.1415926535, 2)   3.14    # 2 decimal places, still a float
round(3.7)               4       # no places given: you get an int
JS habit that breaks here When a number is exactly halfway, Python rounds to the nearest even number. This rule is called round half to even, or banker's rounding:
JavaScript 
Math.round(2.5)   3
Math.round(3.5)   4
Python 
round(2.5)        2
round(3.5)        4
It isn't a bug. Always rounding .5 up pushes totals upward over many numbers. Rounding to even balances out, which is why banks use it. Only exact halves are affected: round(2.6) is still 3.

New words in this section

Round half to even (banker's rounding)
When a number is exactly halfway, round to whichever neighbour is even. 2.5 → 2, 3.5 → 4.Math.round always rounds .5 up

5. Order of operations

Same as school maths, and the same as JS. You may remember it as PEMDAS, or BODMAS in India:

  1. Parentheses (brackets) first
  2. Exponents: **
  3. Multiply and Divide: * / // %, left to right
  4. Add and Subtract: + -, left to right
2 + 3 * 4          14
(2 + 3) * 4        20
2 + 3 * 4 ** 4     770     # 4 ** 4 = 256, then * 3, then + 2
The word lies about M and D PEMDAS has 6 letters but only 4 steps. M and D are one step, a tie. The word puts M before D only because a word needs some order. Inside a tie, you don't pick by letter. You go left to right, whichever comes first. The same goes for A and S. 
8 / 2 * 4          16.0    # 8 / 2 = 4.0 first, then * 4
8 / (2 * 4)        1.0     # what "M before D" would wrongly give
10 - 2 + 3         11      # 10 - 2 = 8 first, then + 3
// and % sit in that same tie with * and /. JS works exactly the same way.
One difference A minus sign has two jobs. Between two values, 5 - 2, it's the subtract operator from §2, a binary operator. In front of a single value, -2, it means "negative". That second kind is called a unary minus ("unary" means one value). Python runs ** before a unary minus, so -2 ** 2 means -(2 ** 2):
JavaScript 
-2 ** 2
SyntaxError: Unary operator used
immediately before exponentiation
expression...
Python 
-2 ** 2        -4   # -(2 ** 2)
(-2) ** 2      4
JS refuses to guess and makes you add brackets. Python does the power first, then makes it negative. Same rule as Lesson 2: unsure? Brackets.

6. Floats are approximate

Python's float is the exact same kind of number as JS's, so you already know this one:

JavaScript 
0.1 + 0.2
0.30000000000000004
Python 
0.1 + 0.2
0.30000000000000004
0.1 + 0.2 == 0.3
False

A computer stores floats in binary, and most decimals like 0.1 can't be stored exactly. Tiny mistakes creep in. These are called floating-point errors. They're fine for nearly everything, but never compare floats with ==.

Why this matters for the exercise 10.1 % 10 gives 0.09999999999999964, not 0.1. That's why Exercism's tests for tasks 1, 2 and 5 use assertAlmostEqual, which accepts an answer that matches to about 7 decimal places (docs). So a tiny float error won't fail you there. Tasks 3, 4 and 6 use exact checks.

For money in real apps, Python has two extra number types: Decimal, which stores decimals exactly, and Fraction, which stores things like 1/3 exactly. They live in Python's standard library, the set of extra tools that comes with Python. You switch one on with an import line, like from decimal import Decimal. Exercism mentions them. You don't need either for this exercise, and import gets its own bridge lesson later.

Check yourself: 5 questions

From memory. Getting it wrong here costs nothing.

1. What type is 6 / 2?

float. / always returns a float, even when it divides evenly: 6 / 2 is 3.0. For a whole-number answer, use // or int().

2. What is 127.5 // 5?

25.0. // rounds down, but a float going in means a float coming out. This is the catch Exercism's hint warns about.

3. What does int("4.5") give?

ValueError. int() on text needs the whole text to be a whole number. (int(4.5), the float, would give 4. JS's parseInt("4.5") would give 4 too.)

4. What is round(2.5)?

2. Exact halves go to the nearest even number. round(3.5) is 4, round(2.5) is 2.

5. What happens with 1 / 0?

ZeroDivisionError. Python stops instead of giving a strange value. Same for // and %.
