1. True and False, with capital letters

Python's yes/no type is called bool. It has exactly two values, and they start with a capital letter.

JavaScript 
let done = true;
typeof done
"boolean"
Python 
done = True
type(done)
<class 'bool'>
JS habit that breaks here Your fingers will type true. To Python that's just a name nobody assigned: 
done = true
NameError: name 'true' is not defined. Did you mean: 'True'?
Same for false. Remember from Lesson 1: Python reads the whole error and even suggests the fix.

New words in this section

bool / Boolean
The type with only two values, True and False. "Boolean" is the general word, bool is Python's name for the type.the boolean type

2. and, or, not: words, not symbols

Python spells the logic operators out in English. In a and b, and is the operator (the thing doing the work) and a, b are its operands (the values it works on). Words like and, or and not are keywords: words Python reserves for itself, so you can't use them as variable names.

JavaScript 
a && b     // both true
a || b     // at least one true
!a         // flip it
Python 
a and b    # both true
a or b     # at least one true
not a      # flip it
JS habit that breaks here &&, || and ! on their own aren't Python. Each one is a SyntaxError: invalid syntax, and this time there's no "did you mean" hint, so you have to spot it yourself. A SyntaxError means Python can't even read the line, like a grammar mistake, so nothing in the file runs. One exception to know: != (not equal) does exist in Python, same as JS.

New words in this section

Operator / operand
An operator is the thing that does the work (and, +). The operands are the values it works on. In a and b, and is the operator, a and b are the operands.same words in JS
Keyword
A word Python has reserved for itself, so you can't use it as a name. and, or, not, def, return, True, None are all keywords. reserved words like function, return, let
SyntaxError
Python can't even read the line, so nothing in the file runs. It's a grammar mistake. SyntaxError, same name

3. Mixing them: which one goes first

When one line has several operators, Python does them in a fixed order. This order is called precedence. From first to last:

OrderPythonExample
1stcomparisons: == != < > is1 == 2
2ndnotnot a
3rdanda and b
4thora or b
 
not True and True          False   # (not True) and True
not (True and False)       True    # brackets go first
True or False and False    True    # True or (False and False)

The and-before-or part is the same as JS's && before ||. The difference is where not sits.

JS habit that breaks here In JS, ! grabs the value right next to it first. In Python, not comes after comparisons, so it flips the whole comparison:
JavaScript 
!1 == 2
// (!1) == 2  →  false == 2
false
Python 
not 1 == 2
# not (1 == 2)  →  not False
True
The rule that keeps you safe: when you mix operators and aren't sure, add brackets. Brackets always go first, and they make the line easier to read.

New words in this section

Precedence
The order Python does operators in when there are several on one line. Like maths: * before +. Brackets beat everything.same idea, slightly different order for not

4. Short-circuit: the right side might never run

Python stops as soon as it knows the answer. This is called short-circuit evaluation. If the left side of and is false, the answer is already false, so the right side is skipped. If the left side of or is true, the answer is already true. Same as JS.

def boom():
    print("boom ran")
    return True

print(False and boom())    False       # boom() never called
print(True or boom())      True        # boom() never called
print(True and boom())     boom ran
                           True        # had to check the right side

Why it matters: if the right side is a function call (say, a slow API call), short-circuit decides whether it happens at all.

New words in this section

Short-circuit evaluation
Stopping early once the answer is known, so the right side of and/or may never run.exactly how && and || behave

5. Truthiness: what counts as false

Like JS, Python lets any value stand in where a True/False is expected. bool() tells you which way a value goes. The Python rule fits in one line:

The whole rule False, None, zero, and anything empty count as false. Everything else counts as true.

Most of that matches JS. The differences are the rows marked in red:

JS habit that breaks here In JS, if (items) is true even when items is an empty array, so you write if (items.length). In Python, if items: is already false for an empty list. That's the normal Python way to say "if there's anything in it". (Lists are [] and dicts are {}. You'll meet them properly in chapters 8 and 12.)

Don't compare with == True

Exercism calls this out: write if flag:, not if flag == True:. It's shorter, and it uses truthiness the way Python intends. (You'll see if properly in chapter 4. For now, read it like JS's if, with a colon and an indented body instead of braces.)

Where you'll see this in AI code A missing setting can be None or an empty string "". Both are falsy, so one check covers both: 
if not api_key:
    print("missing key")
You'll write lines like that when your code loads the key for an AI service.

6. and / or give back one of the values

Same as JS: and and or don't always return True or False. They return one of the two values you gave them, the one that decided the answer.

JavaScript 
"" || "guest"     "guest"
"Tarun" || "guest" "Tarun"
0 && 5            0
Python 
"" or "guest"      'guest'
"Tarun" or "guest" 'Tarun'
0 and 5            0

That gives you the "default value" pattern you already use in JS: name = user_name or "guest".

not is different. It always gives back a real True or False: not "" is True, not "hi" is False.

Why this matters for the exercise Exercism's tests for this chapter check that your function returns exactly True or False. They use is True, so "something truthy" isn't enough. The good news: when both values going in are real bools, and/or give a real bool back (True and False is False). Just don't mix in other types.

7. A bool is secretly a number

In Python, bool is a subclass of int: a special version of int that keeps everything an int can do. So True behaves like 1 and False like 0. (Classes and subclasses come properly in chapter 16.)

True == 1          True
True + True        2
isinstance(True, int)   True    # "is True a kind of int?" yes

JS does something similar (true + true is 2 there too), so this isn't much of a surprise. Where it shows up later: adding up bools is a quick way to count how many things are true.

But True and 1 are still not the same object. Python's is checks identity: "is this the very same object?", not "are the values equal?". It's like === on objects in your JS course, same reference, not same contents:

1 is True
False
SyntaxWarning: "is" with 'int' literal. Did you mean "=="?

Python answers False and also warns you. A warning isn't an error, so the code still runs, but it means "you probably wrote the wrong thing". It says "int literal" because a literal is a value typed straight into the code, like the 1 here. Use == to compare values. is is mainly for checking None: if result is None:.

Check yourself: 5 questions

From memory. Getting it wrong here costs nothing.

1. Which line is valid Python?

Right. Lowercase English words: and, or, not. && is a SyntaxError. AND is one too, because Python is case-sensitive, but for that one it even suggests Did you mean 'and'?

2. What is bool([]) in Python?

False. Anything empty is falsy in Python. This is the opposite of JS, where an empty array is truthy.

3. What does not 1 == 2 give in Python?

True. Comparisons go before not, so it's not (1 == 2), which is not False. JS's !1 == 2 gives false, because ! grabs the 1 first.

4. A test checks result is True. Which result fails it?

Right. 1 and 1 gives back the operand 1, which is truthy but isn't True. The other three are all the real True: comparisons and not always return a real bool.

5. What does True + True give?

2. bool is a subclass of int, so True acts as 1 in maths.
