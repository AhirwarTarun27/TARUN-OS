# IE11 — what it is, and what supporting it costs

Used by: [bullet 1](../dwellworks/01-bundles-ie11.md)

## What it is

**Internet Explorer 11.** Microsoft's old browser — released **2013**, replaced by Edge, support
formally ended **June 2022**.

It predates modern JavaScript. No arrow functions, no `let`/`const`, no classes, no promises, no
`fetch`, no modern CSS (grid, custom properties).

## Why anyone still supports it

Large enterprises froze on it because their **internal line-of-business software was built for it**.
So corporate IT locks employees to IE11 and will not budge.

That is exactly where your users are: **corporate transferees inside locked-down enterprise IT.**

**Say this, because it reframes the whole thing:** supporting IE11 is not neglect or legacy debt. It
is the **customer's environment**, and it is contractual.

## How it is held in Odin

```
modern JS you write                    what IE11 receives
───────────────────                    ──────────────────
const x = () => {…}    ──┐
class Foo {…}            ├─ @babel/preset-env ──▶  var x = function() {…}
[...arr]                 │      (transpile)        ES5 only
async/await            ──┘

Promise, fetch, Object.assign  ──▶  core-js + babel-polyfill  ──▶  shipped as code
Blob gaps                      ──▶  blob-polyfill
react-hook-form                ──▶  webpack alias → its IE11 build
React                          ──▶  pinned to 16.x  (17+ dropped IE11)
Node toolchain                 ──▶  pinned 12.18.1  (frozen with the target)
```

**Transpile** = rewrite modern syntax into old syntax. **Polyfill** = ship a hand-written
implementation of a missing API.

## What it costs — this is the real answer

- **Bundle size.** Polyfills ship to *every* user, including the ~95% on modern browsers who don't
  need them.
- **No modern CSS.** No grid, no custom properties.
- **Library ceiling.** You cannot adopt anything that has dropped IE11 — which by now is most things.
- **The toolchain freezes with it.** React 16, webpack 4, Node 12. You are stuck on all of them.

## "How would you get off IE11?"

A strong answer, because it connects two of your bullets:

> *"Measure first — the GA4 instrumentation gives us actual IE11 sessions by role. My expectation is
> it's transferees inside a handful of corporate networks, not consultants. If that's true you don't
> need a big-bang migration: serve a differential bundle so modern browsers stop paying the polyfill
> tax, agree a sunset date with the client's IT contacts, and unfreeze the toolchain behind it. The
> constraint is contractual, not technical, so the work is mostly evidence and negotiation."*

Linking the analytics bullet to the IE11 bullet is what makes this senior rather than a complaint.
