Lesson 1 · Module 1 — JavaScript Foundations

Types & Coercion

Why a variable can be anything, the 8 types, and the rules that turn "guess the output" from luck into logic.

Why this is Lesson 1 Interviews open here, and it's load-bearing: coercion — JavaScript silently converting one type into another — is the hidden engine behind roughly half the ebook's output questions. Own it now and those "trick" questions stop being tricks. Everything later (scope, closures, this) assumes you're fluent with types.

1 · JavaScript is dynamically typed

You never declare a variable's type. The same variable can hold a number, then a string, and JavaScript won't complain — because type checks happen at run time, as the program executes, not before.

let a;
a = 0;
console.log(a);      // 0        (a number)
a = "Hello";
console.log(a);      // "Hello"  (now a string — totally fine)
Say this in the interview "JavaScript is dynamically typed — types are resolved at run time, so a variable can hold any type and be reassigned to another. TypeScript is statically typed: those checks move to compile time."

2 · The types: primitive vs non-primitive

There are 7 primitive types and then objects. Primitives are immutable and compared by value; everything else is an object (compared by reference — we'll feel that difference in Module 5).

  • Primitives (7): string, number, boolean, null, undefined, bigint, symbol
  • Non-primitive: object — and arrays, functions, dates are all objects underneath
Memory hook "Seven primitives — string, number, boolean, null, undefined, bigint, symbol — everything else is an object." Interviewers love when you know bigint and symbol; most candidates forget them. MDN: Data types

3 · typeof — and its two famous liars

typeof returns a type as a string. Learn the normal cases, then memorize the two that surprise everyone:

typeof "John"      // "string"
typeof 33          // "number"
typeof 3.14        // "number"   (no separate float type)
typeof true        // "boolean"
typeof 1234n       // "bigint"
typeof Symbol()    // "symbol"
typeof undefined   // "undefined"

// The two you must not miss:
typeof null        // "object"   ← historical bug, kept for back-compat
typeof NaN         // "number"   ← NaN is a numeric value ("Not a Number", but a number type)
typeof [1,2,3]     // "object"   ← arrays are objects
Interview gold "typeof null is 'object' — a long-standing bug kept for backwards compatibility. And typeof NaN is 'number', because NaN is a special value of the number type." Two crisp facts that signal depth.

4 · undefined vs null vs undeclared

Three "nothing" states people blur together:

What's the difference between undeclared, undefined, and null?

  • undeclared — the variable was never created. Accessing it throws a ReferenceError.
  • undefined — declared but no value assigned yet. JavaScript's default "empty." It's a type and a value.
  • null — an intentional "no value," assigned by you to say "deliberately empty."
let x;
console.log(x);          // undefined  (declared, unassigned)
let y = null;
console.log(y);          // null       (you chose emptiness)
console.log(z);          // ReferenceError: z is not defined (undeclared)

5 · == vs === (the coercion gate)

This is where coercion first bites. === is strict: it compares value and type, no conversion. == is loose: if the types differ, it coerces one to match the other, then compares.

5 === "5"    // false — number vs string, no conversion
5 ==  "5"    // true  — "5" is coerced to 5 first
0 ==  false  // true  — false coerces to 0
null == undefined  // true  — special-cased as equal
null === undefined // false — different types
The one-liner "Always use === in real code to avoid surprise coercions. == only exists in interviews to test whether you understand coercion." MDN: Equality & sameness

6 · The + coercion rule (memorize this)

The + operator is overloaded — it does math or string concatenation. One rule decides which, and it unlocks a pile of output questions:

The rule If either side of + is a string, JavaScript converts the other side to a string and concatenates. Otherwise it converts both to numbers and adds. (Booleans → true=1, false=0 when going numeric.) Evaluation is left to right.

Now predict these before revealing

What is 3 + 2 + "7"?

"57". Left to right: 3 + 2 are both numbers → 5. Now 5 + "7" — one side is a string, so 5 becomes "5" → "57".

What is true + 1?

2. No string in sight, so go numeric: true → 1, then 1 + 1 = 2.

What is true + "1"?

"true1". A string is present, so both go to string: true → "true", concatenated with "1" → "true1". (Careful: the boolean stringifies to the word "true", not to "1".)

What is const s = "hello"; s.data = "val"; console.log(s.data)?

undefined. Strings are primitives — they can't hold properties. JavaScript wraps "hello" in a temporary String object to run the assignment, then throws that wrapper away. Reading s.data back finds nothing → undefined. This is the payoff of "primitives are immutable."

7 · Retrieval check

No peeking at the notes above. Answer, then read the explanation.

What does typeof null return?

"object". A historical bug in the very first JavaScript engine, now permanent for backwards compatibility. It's the single most-quoted typeof quirk.

Evaluate: 1 + 2 + "3"

"33". Left to right: 1 + 2 = 3 (both numbers), then 3 + "3" hits a string → "3" + "3" → "33".

Which comparison is true?

0 == false. Loose == coerces false to 0, so they match. The strict === ones all fail on differing types, and null === undefined is false (only == treats them as equal).
Bonus (harder): why is 1 < 2 < 3 true but 3 > 2 > 1 false?

Comparison is also left-to-right and returns a boolean, which then coerces to a number. 1 < 2 → true → 1; then 1 < 3 → true. But 3 > 2 → true → 1; then 1 > 1 → false. Same coercion rule, sneaky result.
